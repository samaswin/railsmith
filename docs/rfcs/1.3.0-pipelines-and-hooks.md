# RFC: Railsmith v1.3.0 — Pipelines & Hooks

**Status:** Draft  
**Author:** Railsmith Core  
**Created:** 2026-04-20  
**Target Release:** v1.3.0 (Q3 2026)

---

## Summary

This RFC specifies the public API and internal architecture for two new capability areas in Railsmith v1.3.0:

1. **Lifecycle Hooks** — `before` / `after` / `around` callbacks on service actions, with conditional execution and inheritance.
2. **Service Pipelines** — sequential composition of services under a single entry point, with fail-fast behavior, rollback/compensation, and conditional steps.

A third area—fluent result chaining (`Result#and_then`, `#or_else`)—is covered at the end as an ergonomic add-on that does not require infrastructure changes.

---

## Motivation

Railsmith v1.2 provides strong primitives for single-service operations (inputs, associations, bulk, instrumentation). Two recurring pain points drive this release:

**Cross-cutting concerns repeat across services.** Audit logging, event publishing, and performance tracking are copy-pasted into individual action methods. There is no clean way to express "run this before every `create` in the Commerce domain."

**Multi-step flows lack composition.** Checkout, onboarding, and data migrations require calling three to seven services in sequence. Callers re-implement fail-fast, error wrapping, and (sometimes) rollback logic in controllers or background jobs—outside the service layer where it belongs.

---

## Non-Goals

- Parallel step execution (deferred to a later release).
- Retry/back-off on failure (out of scope; left to job queue).
- Dynamic pipeline construction at runtime (pipelines are declared at class load time).
- Replacing `CrudTransactions`—database transactions remain at the service level; pipeline rollback is compensation logic, not DB rollback.

## Public API

### 1. Lifecycle Hook DSL

Hooks are declared on any `BaseService` subclass (or globally via `Railsmith.configure`).

```ruby
class OrderService < Railsmith::BaseService
  # Simple before hook on a single action
  before :create do
    AuditLog.record(action: :create, actor: context[:actor_id])
  end

  # Before hook on multiple actions
  before :create, :update do |params|
    params[:updated_at] = Time.current
  end

  # After hook — receives the Result produced by the action
  after :create do |result|
    EventBus.publish("order.created", result.value) if result.success?
  end

  # Around hook — must yield to execute the action
  around :create do |action|
    start = Process.clock_gettime(Process::CLOCK_MONOTONIC)
    result = action.call
    elapsed = Process.clock_gettime(Process::CLOCK_MONOTONIC) - start
    Metrics.record("order.create.duration", elapsed)
    result
  end

  # Conditional hooks
  before :destroy, if: :admin? do
    notify_stakeholders
  end

  before :update, unless: ->(svc) { svc.params[:draft] } do
    validate_publish_state
  end
end
```

**Subclass behavior:**

```ruby
class SubscriptionService < OrderService
  # Parent hooks run first, then child hooks, in declaration order.
  before :create do
    ensure_no_duplicate_subscription
  end

  # Opt out of a specific inherited hook by name (hooks must be named to be skippable)
  before :create, name: :audit_log do
    AuditLog.record(action: :create, actor: context[:actor_id])
  end

  skip_before :create, :audit_log
end
```

**Global hooks:**

```ruby
Railsmith.configure do |config|
  config.before_action :create do
    RateLimiter.check!(context[:actor_id])
  end

  config.after_action :create, :update do |result|
    MetricsCollector.record(result)
  end

  # Domain-scoped global hooks
  config.around_action :create, only: [:commerce] do |action|
    CommerceSandbox.wrap { action.call }
  end
end
```

**Execution order (innermost = action):**

```
global before hooks (in declaration order)
  → class-level before hooks (parent → child, declaration order)
    → around hooks (outermost first, each must yield)
      → [action method]
    → around hooks (unwinding)
  → class-level after hooks (parent → child, declaration order)
global after hooks (in declaration order)
```

### 2. Pipeline DSL

```ruby
class CheckoutPipeline < Railsmith::Pipeline
  # Basic step
  step :validate_cart,   service: CartService,     action: :validate
  step :reserve_stock,   service: InventoryService, action: :reserve
  step :charge_payment,  service: PaymentService,  action: :charge

  # Step with rollback compensation
  step :reserve_stock,
       service: InventoryService,
       action:  :reserve,
       rollback: :release

  # Step with explicit input mapping (rename/filter params for this step)
  step :charge_payment,
       service: PaymentService,
       action:  :charge,
       inputs:  { payment_method: :method, amount_cents: :total }

  # Conditional step
  step :apply_coupon,
       service: CouponService,
       action:  :apply,
       if: ->(ctx) { ctx[:coupon_code].present? }

  step :send_confirmation,
       service: NotificationService,
       action:  :send_email,
       unless: ->(ctx) { ctx[:suppress_email] }
end

# Invocation — same interface as BaseService
result = CheckoutPipeline.call(
  action:  :run,
  params:  { cart_id: 42, payment_method: "stripe", coupon_code: "SAVE10" },
  context: current_context
)

result.success?        # => true / false
result.value           # => merged output of all steps
result.meta[:pipeline] # => { name: "CheckoutPipeline", steps_run: 3, duration_ms: 87 }
```

## Internal Data Structures

### StepExecution

Represents the resolved state of a single pipeline step after it has run (or been skipped/rolled-back). Immutable value object.

```ruby
# lib/railsmith/pipeline/step_execution.rb
module Railsmith
  class Pipeline
    StepExecution = Data.define(
      :name,        # Symbol  — step name as declared
      :service,     # Class   — service class invoked
      :action,      # Symbol  — action called on service
      :status,      # Symbol  — :success | :failure | :skipped | :rolled_back
      :result,      # Railsmith::Result | nil (nil when skipped)
      :rollback_result, # Railsmith::Result | nil (set after rollback attempt)
      :started_at,  # Float   — Process.clock_gettime monotonic
      :finished_at  # Float   — Process.clock_gettime monotonic
    ) do
      def duration_ms
        return nil unless started_at && finished_at
        ((finished_at - started_at) * 1000).round(2)
      end

      def skipped?   = status == :skipped
      def success?   = status == :success
      def failure?   = status == :failure
      def rolled_back? = status == :rolled_back
    end
  end
end
```

### HookChain

An ordered, frozen list of `HookEntry` records for a given action on a given service class. Built once at class-load time and shared (never mutated per-call).

```ruby
# lib/railsmith/hooks/hook_chain.rb
module Railsmith
  module Hooks
    HookEntry = Data.define(
      :type,        # Symbol  — :before | :after | :around
      :actions,     # Array<Symbol> — actions this hook applies to
      :block,       # Proc    — the hook body
      :condition,   # Proc | Symbol | nil — evaluated for :if / :unless
      :polarity,    # Symbol  — :if | :unless (default :if)
      :name         # Symbol | nil — named hook, required for skip_before etc.
    )

    HookChain = Data.define(:entries) do
      # Returns entries applicable to a specific action.
      def for_action(action)
        self.class.new(entries: entries.select { |e| e.actions.include?(action) })
      end

      # Returns entries of a given type.
      def of_type(type)
        self.class.new(entries: entries.select { |e| e.type == type })
      end

      # Returns a new chain with entries matching the given name removed.
      def without(name)
        self.class.new(entries: entries.reject { |e| e.name == name })
      end

      def empty? = entries.empty?
    end
  end
end
```

**Registry (per-class, class-level):**

```ruby
# lib/railsmith/hooks/hook_registry.rb
module Railsmith
  module Hooks
    class HookRegistry
      def initialize
        @chain = HookChain.new(entries: [])
      end

      def add(entry)
        @chain = HookChain.new(entries: [*@chain.entries, entry])
      end

      # Called during class inheritance to produce a deep copy.
      def dup
        self.class.new.tap { |r| r.instance_variable_set(:@chain, @chain) }
      end

      def chain = @chain
    end
  end
end
```

## Param Forwarding Contract

### Merge Semantics

When a pipeline step completes successfully, the next step receives merged params:

```
next_params = original_pipeline_params.merge(accumulated_value)
```

Where `accumulated_value` starts as `{}` and is updated after each successful step:

```
accumulated_value = accumulated_value.merge(step_result.value || {})
```

**Rules:**

1. `original_pipeline_params` are never mutated. A frozen deep-dup is taken at pipeline entry.
2. Step outputs take precedence over original params on key collision (later writes win).
3. `result.value` must be a `Hash` or `nil`. A non-Hash value raises `Railsmith::Pipeline::InvalidStepValueError` at pipeline startup (not at runtime), so failures are caught early via a dry-run validation step.
4. Explicit `inputs:` mapping is applied **after** the merge, and only the mapped keys are forwarded to that step. Keys not listed in `inputs:` are dropped for that step (but remain in `accumulated_value` for subsequent steps).

### Example

```ruby
# Original params: { cart_id: 1, coupon_code: "X" }
# Step 1 (validate_cart) returns: Result.success(value: { cart: <Cart>, total_cents: 5000 })
# After step 1 accumulated_value: { cart: <Cart>, total_cents: 5000 }
# Step 2 receives: { cart_id: 1, coupon_code: "X", cart: <Cart>, total_cents: 5000 }

# Step 2 declares inputs: { amount_cents: :total_cents }
# Step 2 actually receives: { amount_cents: 5000 }
```

### Collision Warning

If a step declares `inputs:` that would shadow a key already in the merged params without an explicit mapping, Railsmith logs a warning (not an error) in development and test environments.

## Changes Needed in BaseService

Phase 1 identifies; Phase 2 implements. No code changes land in Phase 1.

| Change | Mechanism | Why |
|--------|-----------|-----|
| Expose `execute_action` as a hook insertion point | Already `private`; needs to call `HookChain` when `Hooks` module is included | Hooks wrap the existing action dispatch |
| Add `inherited` hook in `BaseService` to dup `HookRegistry` | Class macro | Ensures subclasses start with a copy of parent's registry, not a shared reference |
| Make `call` entry point hook-aware | Prepend or include `Hooks` module after `ContextPropagation` | Global hooks run before class hooks; both run before the action |
| Expose `skip_before` / `skip_after` / `skip_hook` class methods | Defined in `Hooks` module | Allow subclasses to opt out |
| Add `Pipeline` as a parallel class to `BaseService` | Does not inherit from `BaseService`; composes with it | Pipelines have a different dispatch loop; reusing `BaseService` would require too many overrides |

## Backwards Compatibility

- All changes are additive. Existing `BaseService` subclasses run identically with no hooks declared.
- `Pipeline` is a new top-level class; no existing class hierarchy is modified.
- `Result` gains `and_then` / `or_else` / `on_success` / `on_failure` instance methods; frozen semantics are preserved (these methods return a new `Result`, they do not mutate).
- Global hook configuration keys (`before_action`, `after_action`, `around_action`) are new keys on `Railsmith::Configuration`; existing configure blocks are unaffected.

---

## Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Hook ordering surprises, especially with inheritance and `skip_*` | Medium | `Service.hooks_for(:action)` introspection helper; verbose logging in dev |
| Param collision between step outputs and original params | Medium | Clear `InvalidStepValueError` at pipeline boot; explicit `inputs:` mapping |
| Rollback semantics unclear to users | High | Heavy docs, sample app, explicit idempotency warning in ADR-0001 |
| Around-hook misuse (forgetting to yield) | Low | Raise `Railsmith::Hooks::AroundHookNotYieldedError` if block returns without calling action |
